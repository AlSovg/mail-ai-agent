# Исследование: Почта Mail и платформы VK / MAX

Дата: 2026-09-29. Источники: **[оф.]** — официальная документация, **[втор.]** — сторонние блоги/новости (требуют перепроверки перед решениями).

## 1. Почта Mail: варианты доступа

Доступ к ящику — только по протоколам IMAP/SMTP (публичного REST API писем не найдено).

| Способ | Как работает | Оценка |
|---|---|---|
| **OAuth Mail** | Код авторизации + PKCE (S256), `oauth.mail.ru`. Scope: `openid email profile mail.imap offline_access`. IMAP/SMTP по `AUTH=XOAUTH2` **[оф.** o2.mail.ru/docs**]** | Основной путь: пароль не хранится, доступ отзывается |
| Пароль для внешних приложений | Генерация в id.mail.ru → Безопасность; нужен включённый IMAP/SMTP в настройках **[втор.]** | Запасной путь, хуже по безопасности (хранится секрет) |

Параметры OAuth **[оф.]**:
- `access_token` живёт `expires_in` (в примере 3600 с).
- `refresh_token` действителен **30 суток после последнего получения access_token**; для него нужны `offline_access` + `prompt=consent`. Агент, который не заходит в ящик месяц, теряет доступ и требует повторного согласия.
- Есть `introspect` токена и `userinfo`.
- Серверы: `imap.mail.ru:993`, `smtp.mail.ru:465` (SSL/TLS).
- IMAP CAPABILITY: `IMAP4rev1 UIDPLUS MOVE XOAUTH2`.

**Ключевой вывод для безопасности.** Scope `mail.imap` не делится на чтение и запись: внешний сервис получает право читать, удалять и отправлять письма от имени пользователя (**[втор.]** справка Mail). Ограничение «только чтение и черновики» нельзя задать на стороне Mail. Его нужно **обеспечивать в нашем коде**: коннектор не содержит операций отправки и удаления, пока не введено подтверждение. Это аргумент в пользу отдельного, минимального почтового слоя.

Проверено 2026-09-29 **[оф.]** (o2.mail.ru/docs, id.vk.com/.../oauth-mail/create-application):
- Приложение создаётся самому в кабинете `https://o2.mail.ru/app/` (форма: фото, redirect_uri, права). Модерация в документации не упоминается. При использовании API Mail принимается [Оферта](https://help.mail.ru/developers/oauth/la) — её нужно прочитать.
- **С 1 июля 2025 OAuth Mail «работает только для продуктовых запросов»**: кнопку входа через Mail предлагают делать через VK ID. Доступ к API Mail (почта, Облако) по-прежнему описан как рабочий. Что значит «продуктовые запросы» и подходит ли нам публичный сервис — не раскрыто, нужен вопрос в поддержку.
- Запрошенный `scope` должен совпадать с правами, указанными в настройках приложения (иначе `invalid_scope`).
- У «пароля для внешних приложений» уровни доступа: «Только отправка», «Полный доступ к Почте» и т. п. Режима «только чтение» нет **[оф.: help.mail.ru/mail/login/mailer]**. Это подтверждает вывод выше.

Не проверено: создание черновика через IMAP `APPEND` в папку «Черновики» (общий паттерн для IMAP работает, у Mail — только spike); лимиты IMAP-соединений.

## 2. Продукты и ИИ Mail (конкуренты «изнутри»)

- **Mail.ru web**: «Краткий пересказ» письма (2–4 предложения); по данным VK, в открытой бете им пользовались 47,8% участников **[втор.]**. Это подтверждает спрос на пересказ, но функция работает внутри интерфейса почты, не в мессенджере.
- **VK WorkSpace** (корпоративная, тарифы «Базовый», «Расширенный», «Индивидуальный», ~207–367 ₽/мес за пользователя по сторонним данным **[втор.]**): AI Ассистент с суммаризацией писем и чатов (с 11.2024). Обновление 09.2026: единый ИИ-ассистент, умный поиск по смыслу, **MCP-сервер для ИИ-агентов**; ассистент в SaaS появится в октябре 2026, работа с почтой обещана позже **[втор.]**.
- Потребительские тарифы Почты Mail и их ИИ-функции: **не найдено**, требуется отдельный поиск.

**Риски и возможности.** VK сама движется к ИИ над почтой (риск: встроенные функции закроют часть нашего сценария). Сегмент, где мы отличаемся: **личные пользователи и малый бизнес на бесплатной Почте Mail, доступ через мессенджер**. Стоит проверить, откроется ли MCP-сервер для потребительских ящиков.

## 3. Платформы бота

| Критерий | MAX | VK (бот сообщества) |
|---|---|---|
| Кто может создать бота | Только верифицированные **юрлица, ИП, самозанятые — резиденты РФ**; физлицам нельзя **[оф.]** | Владелец сообщества |
| Модерация | Да, до 48 ч по рабочим дням; токен выдаётся после неё **[оф./втор.]** | Нет (модерация контента сообщений) **[втор.]** |
| Получение событий | Webhook: HTTPS, порт 443, доверенный сертификат или Минцифры, ответ 200 за 30 с, секрет в `X-Max-Bot-Api-Secret`. Long Polling — только разработка **[оф.]** | Long Poll или Callback API **[втор.]** |
| Кнопки подтверждения | Inline-клавиатура, до 210 кнопок; callback **[оф./втор.]** | Inline и callback-кнопки (до 50) **[втор.]** |
| Лимиты | 30 rps на домен API, 2 сообщения/с в диалог, 4000 символов **[втор.]** | 20 rps с токеном сообщества, 4096 символов, ~5000 рассылок в сутки **[втор.]** |
| Инициатива бота | Нужен `/start` (`bot_started`) от пользователя **[оф.]** | Пользователь должен разрешить сообщения; иначе ошибка 901 **[втор.]** |
| SDK | Официальные TypeScript и Go; OpenAPI-спека **[оф.]** | Неофициальные и официальные SDK (vk-io, vkbottle, vk-api) **[втор.]** |
| Ограничения по содержанию | Запрещено использовать API для **авторизационных, транзакционных, сервисных и массовых сообщений** вне договора с MAX **[оф.]** (пункт 1.5 Требований, ред. 16.12.25) | Правила рассылок; нарушение отключает сообщения сообщества **[втор.]** |
| Обязанности разработчика | Политика обработки ПДн, юр. сведения, поддержка, защита от подмены/дублирования запросов **[оф.]** | Не изучено |

### Проверка VK по официальной схеме API (2026-09-29)
Сайт dev.vk.com в момент проверки был закрыт («Технические работы»), поэтому использована официальная схема `VKCOM/vk-api-schema` на GitHub. Подтверждено **[оф.]**:
- `messages.send` работает с токеном пользователя и сообщества, поддерживает `peer_id`, `random_id` (защита от дублей) и `keyboard`.
- Есть `messages.isMessagesFromGroupAllowed`: до отправки можно проверить, разрешил ли пользователь сообщения от сообщества.
- Ошибка **901** «Can't send messages for users without permission» и **902** «privacy settings» — отправка без разрешения технически невозможна.
- Коды **6** (too many requests) и **9** (flood control) существуют.

Не подтверждено официально (остаётся **[втор.]**): 20 rps, суточные 5000, 24-часовое окно ответа, правила рассылок и санкции. Сравнить после восстановления dev.vk.com.

### Выводы по платформам
1. **MAX**: у автора есть самозанятость, значит верификация профиля и создание бота доступны; дальше модерация до 48 ч. Открытый вопрос остаётся: попадает ли ежедневная сводка (push от бота по подписке пользователя) под «сервисные сообщения» из п. 1.5. Формулировка не уточняет, нужен запрос в поддержку MAX. Ограничение MAX: не более определённого числа ботов на тип профиля (не изучено).
2. **VK**: порог входа ниже (сообщество и токен); разрешение пользователя обязательно и проверяется по API. Лимиты и правила рассылок нужно сверить с официальной документацией.
3. **IMAP-черновики** проверить нельзя без тестового ящика: нужен spike с `APPEND` в папку «Черновики» на реальном ящике Mail.
3. Оба варианта покрывают потребность MVP в кнопках подтверждения; адаптер остаётся заменяемым.
4. Сообщение из почты уходит в чат мессенджера, поэтому содержимое писем хранится и у платформы. Это надо отразить в согласии и модели угроз.

### Проверка п. 1.5 MAX (2026-09-29) **[оф.]**
Тексты: `dev.max.ru/docs/legal/requirements` (ред. 16.12.25) и `.../rules`.
- П. 1.5 запрещает использовать API для «Авторизационных, Транзакционных и Сервисных сообщений, а также рассылки рекламных, маркетинговых или иных массовых сообщений», кроме случаев, прямо предусмотренных **Договором с Компанией**, независимо от технической возможности.
- Определение: **«Сервисные сообщения» — сообщения, информирующие Пользователей о событиях, статусах и (или) действиях, связанных с использованием услуг, сервисов или функциональностей** (реклама в них не допускается).
- Вывод: ежедневная сводка «пришло N писем, важные: …» по определению **очень похожа на сервисное сообщение** (событие в сервисе Mail), значит **проактивный push от бота формально рискует нарушить п. 1.5**. Ответ на прямой запрос пользователя («что нового?») определению не соответствует однозначно: там нет запрета на диалог, но и разъяснения нет. Прямого ответа в тексте нет — нужен запрос в поддержку MAX.
- Решение для MVP: **режим pull** (сводка по кнопке или по запросу пользователя), push отключён, пока MAX не подтвердит письменно. Это меняет H1 из «ежедневная рассылка» в «сводка по запросу + опциональный push после согласования».
- Дополнительно: размещение возможно только при действующем лицензионном договоре с MAX; п. 4.2 требует защиты от подмены и дублирования запросов; п. 2.1 требует политику ПДн и данные о разработчике.

### Лимиты VK
`dev.vk.com` в момент повторной проверки (2026-09-29) по-прежнему возвращает «Технические работы»; лимиты 20 rps, 5000/сутки и правила рассылок остаются **[втор.]**. Проверить, когда сайт вернётся.

## 4. Открытые вопросы
- Регистрация приложения OAuth Mail: форма без модерации (см. §1); открыт вопрос «продуктовые запросы» после 01.07.2025 и Оферта.
- Можно ли писать черновики в Mail (IMAP `APPEND`) и как они отображаются.
- Push-сводка в MAX под п. 1.5: формально рискует попасть под «Сервисные сообщения» (см. §3); MVP работает в режиме pull, вопрос в поддержку MAX.
- Официальные лимиты и правила VK для проактивных сообщений (после восстановления dev.vk.com).
- Потребительские тарифы Почты Mail и её ИИ-функции.
- Обработка ПДн по 152-ФЗ при статусе самозанятого (оператор ПДн, уведомление РКН).
- Spike: IMAP `APPEND` в «Черновики» на тестовом ящике Mail.
